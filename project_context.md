# Контекст проекта XAUUSD — для передачи между Claude и Grok

> Этот файл — "память" проекта. Когда переключаешься между Claude и Grok,
> скопируй актуальную версию этого файла в начало нового чата, и ИИ

## Что мы делаем

Помощник по анализу золота (XAUUSD) с двумя направлениями:

1. **MQL5-индикаторы** для MetaTrader 5 — два варианта:
   - Классический (EMA/RSI/ATR на H4/M30/M5)
   - SMC (Smart Money Concepts: bias на H4, liquidity sweep + MSS на M30,
     вход через FVG на M5) — основан на материалах из книг
     "Daily Bias", "Liquidity Explained", "Smart Money Secrets"

2. **HTML-дашборд** с макро-анализом — живая цена золота (через бесплатный
   API gold-api.com, автообновление каждый час) + мини-график движения цены
   (пробует исторический эндпоинт API, иначе копит точки в реальном времени
   прямо в открытой странице) + таблица макрофакторов (ставка ФРС, инфляция,
   доллар, геополитика, спрос центробанков) + календарь событий + общий
   вердикт long/short

## Важный формат, который нужно сохранять

Каждое объяснение термина или фактора строится так:
**Оригинал/факт → "Простыми словами" (объяснение для школьника) → вывод**

Пример формата, который нужно повторять:
> Реальная доходность облигаций США — 2.2% годовых.
> **Простыми словами:** золото процентов не платит. Если облигации дают
> хороший доход, часть денег уходит туда, а не в золото.
> → медвежий фактор для золота

## ПРАВИЛО: обучение механике, не просто перевод (добавлено 27 июня 2026)

Человеку важно не просто разовое объяснение термина, а чтобы со временем
он сам понимал логику без подсказок — построить картину в голове, а не
зависеть от перевода каждый раз.

Поэтому для тематических блоков (факторы золота, COT-отчёт и т.д.)
добавлены раскрывающиеся (`<details>`) обучающие блоки "Как это работает —
логика, а не перевод", которые объясняют ПРИЧИННО-СЛЕДСТВЕННУЮ механику,
а не просто переводят термин. Пример разницы:
- Перевод (недостаточно): "Красный = экстремально много шортов"
- Механика (то, что нужно): почему позиция становится "экстремальной"
  (группа близка к пределу своих возможностей двигать рынок), и почему
  красный шорт у банков может быть бычьим сигналом через механизм short
  squeeze (закрытие шортов = доп. спрос = рост цены)

При добавлении новых терминов/факторов в любой будущий дашборд — всегда
добавлять такой обучающий блок с цепочкой рассуждений, не только таблицу
с переводом. Стиль: класс `learn-box` (раскрывающийся блок), внутри
`learn-step` с `learn-step-title` — см. готовый CSS и разметку в
xauusd_dashboard_main.html как образец.

Уже встроенные на этом уровне детализации темы (не упрощать при будущих
обновлениях):
- Откуда физически берётся ставка ФРС (FOMC, ночные межбанковские займы,
  целевой диапазон) и полная цепочка ставка→доходность облигаций→отток
  из золота→цена
- Конкретные примеры компаний для категорий COT (Newmont/Barrick Gold —
  Producer/Merchant; JPMorgan/Goldman Sachs — Swap Dealers), чтобы
  абстрактные названия превращались в понятную картину "кто это реально"
- Логика "зелёный = далеко от исторического предела группы, есть запас
  двигать рынок" / "красный = у предела, запаса нет" + механика short
  squeeze (закрытие шортов банками = доп. спрос = ускорение роста)

## ПРАВИЛО: обновление всегда целиком

Когда человек просит "обнови таблицу" / "обнови дашборд" / "обнови COT" —
это означает обновить **ВСЁ** сразу за один проход, а не одну часть
по отдельности:
- живую цену (она и так автообновляется сама, но проверить актуальность)
- макрофакторы (ставка ФРС, инфляция, доллар, геополитика, доходность
  облигаций, спрос центробанков, техническая картина) — заново искать
  новости
- календарь ближайших событий — обновить даты, отметить что уже прошло
- COT-блок (CFTC) — проверить, не вышел ли новый отчёт (по пятницам)
- общий вердикт long/short — пересчитать с учётом всех новых данных

НЕ обновлять только один блок по отдельности, даже если человек упомянул
конкретное слово (например "обнови COT" — всё равно обновляется весь
дашборд, COT просто в приоритете внимания).

## Ключевые договорённости и принципы (важно не нарушать)

- **Никаких точных прогнозов цены и времени.** Фраза вида "цена упадёт на
  $20 в 15:00" technически невозможна — этого не знает никто, даже банки.
  Можно говорить о направлении факторов и моментах повышенной волатильности
  (выход данных, заседания ФРС), но не о точных числах/времени.
- **SMC — это интерпретация, не доказанный факт.** Идея, что банки
  "специально охотятся за стопами" — предположение трейдерского
  сообщества, а не подтверждённая практика. Объяснять это честно, если
  человек спрашивает.
- **Реальная институциональная торговля** опирается в основном на:
  макроэкономику (ставки, инфляция, ВВП), хеджирование рисков, доступ к
  дорогим данным/аналитике, и крупный размер ордеров, который физически
  двигает цену. Не сводить всё к "охоте за ликвидностью".
- Любой технический инструмент (индикатор, таблица) — это помощник для
  анализа, не гарантия результата. Это нужно повторять при каждой выдаче
  инструмента, не превращать в рекламу точности.

2. Откуда взялась конкретная цифра и что она значит (точное число, период,

### Источники данных (проверены, рабочие):

**Календарь событий:** JBlanked Calendar API (www.jblanked.com/news/api/) —
бесплатный, агрегирует Forex Factory + FxStreet + MQL5. Формат JSON с полями
Name, Currency, Impact, Date, Forecast, Previous. Нужна регистрация для
API-ключа (бесплатная). Альтернатива при проблемах — Economic Calendar API
на RapidAPI (тоже есть free tier).

**Cleveland Fed Nowcasting:** https://www.clevelandfed.org/indicators-and-data/inflation-nowcasting
— живая HTML-таблица, обновляется каждый рабочий день ~10:00 ET. Не JSON API,
нужен HTML-парсинг (BeautifulSoup) таблицы "Inflation, year-over-year percent
change" — там 5 колонок: Month, CPI, Core CPI, PCE, Core PCE, Updated.
Пример данных на 26.06.2026: CPI 3.96%, Core CPI 2.85%, PCE 3.90%,
Core PCE 3.43%.

ВАЖНЫЕ ФАКТЫ про nowcasting для объяснений (5-пунктовый стандарт уже
заготовлен выше в этом файле, в чате тоже объяснено):
- Core-показатели меняются редко (мало источников данных, приходят нечасто)
- Headline (общие) показатели двигаются часто — зависят от цен на бензин →
  от цен на нефть (Brent), которые волатильны и меняются каждый день
- Точность не абсолютна — это оценка по 10 рядам данных, а не по полной
  статистике агентства, НО исторически точнее консенсус-прогнозов
  профессиональных экономистов (Blue Chip, SPF) в среднем
- Используются 10 рядов данных: 5 от BLS (CPI, core CPI, CPI на еду, CPI на
  еду дома, CPI на бензин), 3 от BEA (PCE, core PCE, PCE на еду навынос),
  1 еженедельный (цены на бензин, EIA), 1 ежедневный (нефть Brent)

### Архитектура (3 части):

1. **Новый скрипт** `xauusd_alerts_bot.py` — отдельный от почасового и COT
2. **Workflow** с запуском каждые 15-30 минут (НЕ каждые 5 минут — риск
   слишком частых вызовов GitHub Actions)
3. Логика на каждый запуск:
   - Получить список сегодняшних/завтрашних высокоприоритетных событий
     для USD через Calendar API
   - Если до события ровно ~60 минут ИЛИ ~30 минут — отправить
     предупреждение (с защитой от дублирования, как в почасовом боте —
     отслеживать, какое предупреждение уже отправлено для какого events_id)
   - Если событие касается CPI/PCE — подтянуть свежий Cleveland Fed nowcast
     и включить его в сообщение
   - Отдельно: сравнить текущую цену с ценой из предыдущего запуска
     (хранить в GitHub через тот же commit-механизм или просто in-memory
     между запусками не работает — нужно либо хранить в файле в репо, либо
     в Issue/Gist). Если изменение превышает порог (предлагается 0.3-0.5%
     за 15-30 минут — НЕ финально, нужно откалибровать) — отправить алерт
     "⚡ Резкое движение"
   - Применить проверку is_market_closed() — не слать ничего в выходные
     (как в двух других ботах)

### Формат сообщения-предупреждения (по 5-пунктовому стандарту):
1. Перевод названия события (если аббревиатура)
2. Когда выходит, текущий прогноз и предыдущее значение
3. Кто публикует (BLS/BEA/Fed) и как часто
4. Если CPI/PCE — добавить Cleveland Fed nowcast с объяснением (что такое
   nowcasting, откуда цифра, почему может отличаться от консенсуса)
5. Условный сценарий направления + сводка текущего контекста (доминирующий
   фактор, настрой COT) для самостоятельного решения пользователя — явно
   написать "это не сигнал, а контекст для твоего решения"

## ТРЕТИЙ БОТ ЗАВЕРШЁН И РАБОТАЕТ В PRODUCTION (30 июня 2026)

Полностью реализован, протестирован, в рабочем состоянии. Файлы:
`xauusd_alerts_bot.py` + `.github/workflows/send_alerts.yml`. Workflow
запускается каждые 15 минут (cron `*/15 * * * *`).

### История трёх неудачных попыток с API календаря (ВАЖНО — не пробовать снова):
1. **JBlanked Calendar API** — авторизация работает, но бесплатный лимит
   сократился до **1 запроса в день** на весь аккаунт (объявление на сайте
   про "huge surge in traffic"). Непригоден для проверки каждые 15 минут.
2. **Finnhub Economic Calendar** — общий лимит 60 запросов/минуту звучит
   щедро, но конкретно раздел economic calendar похоже требует платной
   подписки (множество жалоб пользователей на 403 "no access" для разных
   эндпоинтов на free-тарифе).
3. **Trading Economics (guest:guest)** — публичный демо-доступ, который
   был в официальной документации (docs.tradingeconomics.com) с реальными
   примерами по нужным показателям, оказался **полностью отключён**:
   API возвращает 410 "the guest account has been discontinued, please
   subscribe to a plan".

### Финальное решение: ручной календарь
Список `KNOWN_EVENTS` прямо в `xauusd_alerts_bot.py` — каждая запись:
id, name, date_utc (точное время в UTC!), forecast, previous. События
автоматически перестают учитываться через 24 часа после прошедшей даты
(не нужно вручную удалять, но стоит чистить раз в несколько недель для
порядка). Импакт всегда "High" — в список добавляются только заведомо
важные события вручную.

**ПРАВИЛО НА БУДУЩЕЕ:** при каждом "обнови дашборд" — синхронно обновлять
KNOWN_EVENTS новыми датами/прогнозами (брать из того же источника, что и
раздел "Календарь ближайших событий" в HTML-дашборде), закоммитить
xauusd_alerts_bot.py на GitHub через тот же механизм автокоммита.

### Технические детали реализации:
- Хранение состояния между запусками (последняя цена, отправленные
  предупреждения) — через файл `alerts_state.json` в корне репозитория,
  который бот сам читает/обновляет/коммитит через GitHub API при каждом
  запуске (использует встроенный `secrets.GITHUB_TOKEN` от самого GitHub
  Actions, НЕ наш Personal Access Token — для этого в workflow нужен
  `permissions: contents: write`)
- Порог алерта на резкое движение: 0.4% изменения за ≤35 минут — протестирован,
  работает (был случай 0.987% за 178 минут — правильно НЕ сработал, так как
  это не "резкое" движение за такой долгий промежуток)
- Предупреждения за 60 и 30 минут до события, с защитой от дублирования
  через id события + suffix (_60m/_30m) в списке sent_warnings
- Объяснения событий по 5-пунктовому стандарту встроены в словарь
  EVENT_EXPLANATIONS (cpi, pce, non-farm, federal funds rate) — при
  добавлении нового типа события в KNOWN_EVENTS, если его темы нет в этом
  словаре, нужно туда добавить объяснение по тому же стандарту
- Cleveland Fed Nowcast автоматически добавляется в сообщение, если
  название события содержит "cpi" или "pce" (регистронезависимо)

### Важный урок про права GitHub PAT (Personal Access Token):
Fine-grained токен с правом **Contents: Read and write** НЕ может изменять
файлы в `.github/workflows/` — для этого нужно отдельное право **"Workflows"**,
которого у созданного токена нет (осознанное решение пользователя —
не расширять права токена ради разовой операции). Поэтому: Python-файлы
(.py) Claude коммитит сам через API, а workflow-файлы (.yml) пользователь
всегда создаёт/редактирует вручную через интерфейс GitHub. Это стабильный,
проверенный паттерн — использовать его и в будущем, не пытаться снова
закоммитить .yml через токен (будет ошибка 403 "Resource not accessible").
